# NAS Mobile PRD（简单版）

## 1. 项目信息

| 项目 | 内容 |
|---|---|
| Language | 中文 |
| Programming Language | 原生安装包优先：React Native + TypeScript；iOS/Android 使用原生安全存储与系统能力（具体 UI/构建框架由研发在技术设计中确定） |
| Project Name | `nas_mobile` |
| 文档版本 | v0.2 |
| 原始需求 | 开发一款区别于飞牛官方 APP 的手机应用，直接连接用户自己的飞牛 NAS；核心集成 NAS 已安装的 OpenClaw、qBittorrent 下载器、Heimdall 服务；设置页支持切换/配置，并允许用户自定义底部导航栏图标及功能顺序。 |

### 产品定位
面向拥有飞牛 NAS 且已自行部署服务的用户，提供“服务直达 + 统一入口 + 可个性化”的移动控制台。产品不替代飞牛官方 APP 的系统管理能力；优先解决 OpenClaw、qBittorrent、Heimdall 在手机端分散访问、操作路径长、入口固定的问题。

---

## 2. 产品定义

### 2.1 产品目标
1. **统一直达**：以 iOS/Android 原生安装包在一个移动应用中提供 OpenClaw、qBittorrent、Heimdall 入口，核心入口首次进入后可在 3 次点击内到达。
2. **安全可控连接**：仅由用户配置其自有 NAS 的局域网地址或远程 HTTPS 域名/反向代理地址；敏感凭据在本地安全存储，应用不代管 NAS、下载器或服务数据。
3. **个性化工作台**：允许用户按使用频率调整底部导航栏的功能顺序与图标，使常用服务始终处于高可达位置。

### 2.2 用户画像

| 用户类型 | 特征 | 核心诉求 |
|---|---|---|
| 自建 NAS 爱好者 | 熟悉 Docker / 反向代理，已部署多个服务 | 用手机集中访问自建服务，减少记忆多个地址与重复登录。 |
| 下载与媒体管理用户 | 高频使用 qBittorrent，关注任务状态与存储 | 随时查看下载进度、暂停/恢复任务，并快速跳转到媒体/导航页。 |
| AI 自动化使用者 | 在 NAS 上运行 OpenClaw，用于对话或自动化任务 | 在移动场景快速发起、查看和继续 AI 任务。 |
| 家庭 NAS 共享成员 | 技术能力有限，经授权使用部分服务 | 只看到获授权的入口，以低学习成本访问常用功能。 |

### 2.3 主要用户故事
1. As a 自建 NAS 用户, I want 在手机应用中配置我的 NAS 与服务地址, so that 我无需反复输入或记忆多个内网/域名入口。
2. As a OpenClaw 使用者, I want 从底部导航一键进入 OpenClaw 并保持会话状态, so that 我能在外出时继续处理 AI 对话或任务。
3. As a qBittorrent 用户, I want 查看下载任务列表、进度及状态并执行基础控制, so that 我能及时管理占用带宽或异常任务。
4. As a Heimdall 用户, I want 在统一入口访问我的服务仪表盘, so that 我能快速跳转至 NAS 中其他已部署服务。
5. As a 高频用户, I want 调整底部导航的图标和顺序, so that 最常使用的功能更容易触达。

## 3. 技术规范

### 3.1 Requirements Pool

#### P0：必须具备
- **原生安装包交付**：必须提供 iOS 与 Android 可安装包；凭据必须使用各平台安全存储，网络、通知、生物识别等能力应通过系统权限机制实现。
- **NAS 双网络连接配置**：支持用户手动配置局域网地址（IP/主机名 + 端口）及远程 HTTPS 域名/反向代理地址；保存前须执行当前网络下的连通性校验并显示成功/失败原因。应用可为同一 NAS 保存局域网与远程地址，按用户选择切换，不得扫描局域网或公网发现设备；支持编辑、删除与切换当前 NAS 档案。
- **服务独立配置**：OpenClaw、qBittorrent、Heimdall 分别支持启用开关、服务地址（可继承当前 NAS 地址或单独覆盖）、必要的认证字段配置；未配置或不可达时展示明确引导，不展示伪数据。
- **OpenClaw 入口**：以安全原生 WebView / 内嵌网页方式进入用户已部署的 OpenClaw 服务；支持加载态、失败重试、在外部浏览器打开；不得改写 OpenClaw 的业务逻辑或绕过其登录校验。
- **qBittorrent 任务浏览与刷新**：通过 qBittorrent Web API 展示任务名称、状态、进度、剩余时间、下载/上传速度、体积与分类/标签；支持下拉刷新、可控自动刷新、按名称搜索、按状态/分类/标签筛选及按名称、进度、速度、添加时间排序。
- **qBittorrent 基础控制**：支持添加磁力链接或 URL、暂停/恢复单任务、批量暂停/恢复、删除任务；删除必须有强确认，默认仅删除任务记录且不勾选“同时删除文件”，用户主动勾选删除文件时须在确认框中再次明确风险。
- **可定制底部导航**：默认提供“首页、OpenClaw、下载、Heimdall、设置”；设置中允许用户选择显示的入口（设置不可隐藏）、调整顺序、为已提供的图标集合选择图标；保存后即时生效并持久化。
- **基础首页**：展示当前 NAS 连接状态、当前连接模式（局域网/远程 HTTPS）、已启用服务状态与常用服务快捷入口；状态必须来自实时或最近一次成功探测，标明刷新时间。
- **错误与空状态**：覆盖无配置、无网络、服务超时、认证失败、证书异常、服务未启用等场景，并提供可执行的下一步操作。

#### P1：应该具备
- **qBittorrent 分类与标签管理**：支持查看、筛选并为单个/多个任务设置或移除分类、标签；仅展示和调用当前用户在 Web UI 权限下可见的对象。
- **qBittorrent 速度限制**：支持查看全局下载/上传限速状态，并设置全局限速或对选中任务设置限速；提交前展示影响范围，失败时反馈服务端权限或版本兼容原因。
- 支持多个 NAS 配置档案，并可快速切换；切换后服务配置与认证信息按档案隔离。
- 首页支持手动下拉刷新，以及连接状态的轻量轮询；轮询频率必须可控，避免无意义耗电和请求压力。
- OpenClaw、Heimdall 支持收藏为首页快捷卡片及一键外部浏览器打开。
- 配置可导出为不含密码/令牌的结构化文件，并可导入；导入前必须展示变更预览与确认。

#### P2：可选增强
- 基于系统通知的下载完成、失败和 NAS/服务离线提醒（需用户显式授权，并依赖安全的通知通道）。
- qBittorrent 的 RSS、队列策略、Tracker/文件明细等高级管理能力。
- 为不同 NAS 配置创建独立导航布局与主题偏好。
- 生物识别解锁应用或关键操作二次验证（依赖宿主平台能力）。
- 服务健康趋势、下载统计与常用入口使用统计（默认仅本地计算）。

### 3.2 核心页面与交互

| 页面 | 核心内容 | 关键交互 |
|---|---|---|
| 首页 | 当前 NAS 名称与连接状态、三项服务状态、快捷入口、最近刷新时间 | 点击服务卡片进入对应功能；下拉刷新；未配置时进入设置向导。 |
| OpenClaw | 内嵌 OpenClaw 页面、加载/错误状态、外部打开入口 | 首次按服务自身规则登录；失败时重试、查看错误提示或跳转服务配置。 |
| 下载（qBittorrent） | 任务名称、状态、进度、剩余时间、大小、下载/上传速度、分类/标签；搜索、筛选、排序、刷新与操作菜单 | P0 支持磁力/URL 添加、单个及批量暂停/恢复、删除任务；删除任务默认不删除文件，勾选删除文件后触发强确认。P1 支持分类/标签编辑与全局/任务级限速。 |
| Heimdall | 内嵌 Heimdall 仪表盘、加载/错误状态 | 保留原服务的卡片跳转；支持外部浏览器打开与重新加载。 |
| 设置 | NAS 档案、局域网/远程 HTTPS 地址、各服务配置与启用状态、连通性检测、导航栏编辑、安全说明 | 用户手动选择当前连接模式；保存前校验必填项，远程地址仅允许 HTTPS；检测结果逐服务展示；导航编辑中拖拽排序、选图标、恢复默认并即时预览。 |
| 首次使用向导 | 产品边界说明、局域网/远程 HTTPS 地址、服务选择与校验 | 可跳过非必要服务；必须明确提示仅连接用户授权的自有 NAS，且不执行任何自动扫描或鉴权绕过。 |

### 3.3 底部导航规则
- 默认顺序：首页、OpenClaw、下载、Heimdall、设置。
- 设置页与至少一个业务入口必须保留；设置页不可隐藏，且始终置于导航栏末位，以避免用户失去配置入口。
- 用户可拖拽调整业务入口顺序、隐藏未启用入口、从预设图标库选择图标；不可上传任意图标（首版避免安全、版权与一致性风险）。
- 自定义结果按当前 NAS 档案本地保存；“恢复默认”须二次确认。

### 3.4 外部服务接入前提

| 服务 | 接入前提 | 首版接入方式 |
|---|---|---|
| 飞牛 NAS | 用户拥有合法管理或访问权限；手机可经局域网访问 NAS，或使用用户自行配置的远程 **HTTPS** 域名/可信反向代理访问；反向代理、域名和证书由用户自行维护 | 用户手动填写局域网与/或远程地址，并手动选择连接模式；应用仅对填写地址做连通性/服务可用性检测，不做局域网或公网扫描。 |
| OpenClaw | 已在 NAS 上部署并可通过浏览器访问；对外访问、SSO/登录策略由用户自行配置 | 安全原生 WebView 承载，复用服务本身会话与鉴权。 |
| qBittorrent | 已启用 Web UI；用户拥有 Web UI 凭据及 API 操作权限；目标版本须支持任务浏览、添加任务、暂停/恢复、删除、分类/标签与限速所需 API；反向代理需正确处理 Cookie、CORS/同源策略等 | 优先使用 Web API；API 能力、认证或版本不兼容时仅提供只读错误说明或安全 WebView 降级，不绕过服务端认证。 |
| Heimdall | 已部署并可通过浏览器访问；用户自行维护其卡片链接及访问控制 | 安全原生 WebView 承载，复用服务本身会话与鉴权。 |

### 3.5 权限与安全边界
- 应用**必须仅连接用户自行填写并授权的 NAS 与服务地址**；不提供局域网/公网扫描、设备发现绕过、默认密码尝试或任何规避访问控制的能力。
- NAS 地址、密码、API Token、会话 Cookie 等敏感信息**不得**上传至自建以外的业务服务器、日志或分析平台；仅存储于 iOS Keychain、Android Keystore 等终端系统安全存储或用户明确选择的加密容器。
- 局域网地址可使用用户明确填写的 HTTP 或 HTTPS；远程访问地址**必须为 HTTPS**。HTTP、私有/自签名证书场景必须弹出明确风险告知并由用户显式确认，不能静默忽略 TLS 校验错误。
- qBittorrent 删除任务、删除文件、修改限速等高影响操作必须二次确认；默认不预选“同时删除文件”。
- 内嵌网页仅允许访问用户已配置的服务域名及其必要跳转域；外部跳转须明确展示目标域名并由用户确认（首版可直接交给系统浏览器处理）。
- 权限最小化：首版不申请通讯录、相册、定位、麦克风等无关权限；通知、生物识别等仅在用户启用相关增强功能时申请。
- 产品不承担 NAS 系统设置、账户权限分配、外网暴露、反向代理、数据备份及第三方服务可用性的管理责任；这些均由 NAS 管理员负责。

### 3.6 验收标准

| 范围 | 可验收标准 |
|---|---|
| 原生交付与配置 | 提供可安装的 iOS 与 Android 包；用户可新建、编辑、删除、切换 NAS 档案，并为同一 NAS 手动填写/选择局域网地址与远程 HTTPS 地址。对每项已启用服务的检测在合理超时内返回“可达 / 认证失败 / 不可达 / 证书异常”等可区分结果。 |
| OpenClaw 与 Heimdall | 在服务地址有效且用户具备权限时，可从导航进入对应服务；加载失败页面提供重试、外部打开和进入配置三种有效路径。 |
| qBittorrent P0 | 对符合 Web API 条件的实例，可浏览任务名称、状态、进度、剩余时间、体积和实时速度；可按名称搜索、按状态/分类/标签筛选并排序、下拉/自动刷新；磁力/URL 添加、单个及批量暂停/恢复均生效。删除必须二次确认且默认不删除文件；勾选删除文件时必须出现强风险确认。 |
| qBittorrent P1 | 可查看/编辑分类和标签，并对单项或批量任务生效；可查看和设置全局或任务级上传/下载限速；服务端权限、版本或 API 不支持时必须反馈可理解的原因，不得伪造成功状态。 |
| 导航自定义 | 用户可调整业务入口顺序、隐藏可隐藏入口、更换预设图标；保存后无需重启即生效，重新打开应用后仍能保留；设置始终可访问。 |
| 安全与隐私 | 不存在局域网/公网扫描、弱口令尝试或鉴权绕过；敏感凭据不出现在界面明文回显、日志与导出文件中；远程地址仅允许 HTTPS，局域网 HTTP 或不受信证书连接会出现风险提示并要求主动确认。 |
| 体验基线 | 无服务配置、网络断开、认证失败、超时等状态均无白屏/崩溃，并提供明确原因与下一步；首页可显示最近一次刷新时间。 |

### 3.7 Open Questions
1. iOS 与 Android 的最低系统版本、分发渠道（应用商店、企业签名或侧载）和签名/上架责任如何确定？
2. 局域网与远程 HTTPS 地址是否需要自动健康切换，还是首版仅允许用户在设置中手动选择？若支持 Tailscale/VPN，其地址应视为局域网还是远程模式？
3. OpenClaw 的部署形态、登录方式、支持的嵌入策略（如 CSP / X-Frame-Options）及移动端适配情况是什么？
4. qBittorrent 的目标版本范围、认证方式（账号密码/反向代理 SSO）和各版本对分类、标签、全局/任务级限速 API 的兼容矩阵如何界定？
5. Heimdall 是否存在 iframe/WebView 限制或需要统一 SSO？其外链域名白名单策略如何定义？
6. 是否存在多用户/家庭共享需求？若有，NAS 端的最小权限账户、配置分享和本地数据隔离规则需如何设计？
7. 用户自定义导航是否需要支持自定义文字、仅预设图标、每个 NAS 独立布局，以及可显示的最大入口数量？
8. 是否需要推送通知、后台刷新与远程唤醒 NAS？这些能力的服务端、权限与耗电预算尚未确定。
